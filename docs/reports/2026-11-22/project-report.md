## 2. 关键链路审计

### 2.1 默认 / 隐藏队列槽位

- 队列类型由成员是否包含隐藏壁纸动态判定，`QueueSlotResolver` 在队列缺失或类型不匹配时返回 `nil`，不会静默回落到其他队列。
- 默认槽不允许为空或指向隐藏队列；隐藏槽允许为空。
- 旧格式迁移把包含隐藏壁纸的活动队列写入隐藏槽，默认槽回退到内置默认队列。
- 隐藏壁纸标记会从“仍为普通队列”的队列中移出成员；已有其他隐藏成员的队列保持不变并转为隐藏队列。
- 切换隐藏模式会销毁旧播放器并按目标槽位重建/恢复队列，符合“状态保留、播放器释放”的既有策略。

**结论**：未发现阻断问题。

### 2.2 壁纸库迁移

- 迁移只复制、不修改源库；目标必须为空，且拒绝同一路径、目标位于源内、源位于目标内。
- 复制失败时清理本次写入的顶层内容，不会留下半成品库。
- 跳过 `.DS_Store` 与 AppleDouble `._*`；统计实际文件数与字节数。
- UI 拒绝临时目录作为迁移目标；删除旧库前再次校验旧库不等于当前库且不是当前库父目录。
- 迁移在后台 actor 串行执行，完成后才切换库配置并刷新界面。

**结论**：未发现阻断问题。迁移需要目标磁盘至少有与当前库等量的可用空间，属于预期行为。

### 2.3 断开显示器与全屏暂停

- 断开显示器仅保留档案与队列记录，不再出现在侧栏、检查器和显示器选择列表。
- 全屏应用只暂停其窗口所在显示器；其他显示器继续播放，退出全屏仅恢复对应屏幕。
- 系统暂停仍按显示器粒度计算，电池策略作用于所有屏幕。

**结论**：未发现阻断问题。

### 2.4 动态分页

- `WallpaperLibraryPageLayout` 根据内容区域宽高、190pt 固定卡片宽度、16pt 基础列间距、24pt 内边距计算列数；窗口变宽时增加列数，富余宽度转为列间距，卡片本身不放大。
- 卡片文本区固定为 56pt（上方 9pt 间距），卡片高度只取决于卡片宽度，分页行数计算与实际渲染一致。
- 列表模式按 76pt 行高和 12pt 上下留白计算可见行数。
- 窗口尺寸或布局模式变化时重算页容量；若当前页首个可见项仍存在，则跳到包含该项的新页面。
- 纯函数测试覆盖 880×700、880×500、880×1000、1200×900、列表高度与零尺寸视口。

**结论**：未发现阻断问题。

### 2.5 窗口工具栏

- 顶部工具栏固定为 76pt 高度；标题和副标题均限制单行，窗口缩放不会因标题换行而改变高度。
- 内容宽度小于 870pt 时切换为图标紧凑布局；搜索、筛选、排序、视图、隐藏、批量、添加和设置入口全部保留。
- 窗口最小宽度由 220pt 侧栏、340pt 检查器、680pt 工具栏内容和 2pt 分隔线组成，共 1242pt。
- `windowWillResize` 与 `windowDidResize` 双重夹紧：真实鼠标拖拽和辅助功能/程序化缩放都会停在最小宽度。
- 实际验证：1440、1600 宽保持完整布局且工具栏高度固定；1422 宽切换为紧凑布局，1242 宽为最小布局，两者工具栏均完整，无控件越界。默认 1440 宽下设置按钮与检查器之间保留安全间距。

**结论**：未发现阻断问题。

### 2.6 版本与发布卫生

- `UpdateService` 与 `SettingsWindowController` 原先各自硬编码 `fallbackVersion: "0.2.7"`；现统一引用 `ApplicationVersionInfo.developmentFallbackVersion = "0.2.11"`。
- 发布检查清单已改为只要求同步这个单一常量。
- 新增 0.2.11 发布说明，README 与文档索引同步到 0.2.11。

### 3.1 本轮发现并修复的测试夹具问题
闸门在真实双屏环境首次运行暴露了两个测试夹具问题，应用逻辑本身无需修改：

1. `queue-pause-runtime-test.sh` 用 `open -a TextEdit` 启动全屏应用；macOS 26 上 TextEdit 无文档时显示“打开文件”对话框，无法进入全屏。改为显式打开一个临时文档。
2. 测试把夹具队列标记为默认队列，应用会把它绑定到所有显示器；`display-playback-bindings.json` 的数组顺序不固定，测试读取 `[0]` 可能读到副屏。改为按夹具显示器名称/ID 定位绑定，并使用 `AXFullScreen` 属性并轮询确认全屏已生效。

修复后该测试连续 3 次独立通过，并在完整闸门中再次通过。
